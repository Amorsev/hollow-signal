# План: хоррор-мод в духе From The Fog / Inside The System / The Broken Script

## Context
Пользователь хочет сделать собственный психологический хоррор-мод для Minecraft, вдохновлённый тремя популярными модами. Рабочая папка `F:\claudecode\horror` пуста — проект с нуля. Платформа: **NeoForge 1.21.1**. Четвёртая стена: по умолчанию **безопасный режим**, по желанию — **хардкор-режим** (файлы на ПК, фейковые системные ошибки с посланиями, краши, выключение ПК).
Мод должен быть оригинальным: свой антагонист, свой лор, свои текстуры/звуки — без копирования Herobrine-скинов, coolplayer303/Aiko, Null и т.п.

Рабочее название: **"Hollow Signal"**, modid `hollowsignal`. Антагонист — «Наблюдатель» (рабочее имя `the_listener`): игрок-подобная сущность, которая «слушает» мир через сигнал.

## 1. Разбор механик исходных модов

### From The Fog (LunarEclipseStudios, датапак + мод)
- Сущность не появляется первые ~3 дня — медленный разгон.
- **Сталкинг**: стоит в тумане/на краю прорисовки, исчезает при взгляде или приближении.
- **Скример**: резкий поворот камеры игрока на сущность + звук.
- **Взаимодействие с миром**: ворует/заменяет факелы, строит странные структуры (пирамиды, кресты, тоннели 2×1), оставляет таблички с текстом, кладёт жуткие предметы в сундуки.
- **Sneaky Strike / Creeping**: подкрадывается сзади и бьёт, если игрок не обернулся (выкл. по умолчанию).
- Поджог построек (выкл. по умолчанию), святилища (shrines), которые он «зажигает» обратно.
- Собаки рычат/скулят рядом с ним — косвенные индикаторы.
- Тонкий конфиг через `/function fromthefog:admin/config`, выбор скинов.

### Inside The System (Forge 1.19–1.21)
- Сюжетный ARG-хоррор: в одиночном мире появляется «игрок» (фейковое подключение в чат), сначала дружелюбный.
- **Система доверия (trust)**: действия игрока (атака, подарки, ответы в чат) двигают шкалу → разные ветки и концовки.
- Диалоги в чате, реакция на сообщения игрока.
- Медленное нагнетание вместо скримеров.
- **4-я стена**: краши игры при плохой концовке, взаимодействие с ПК (окна, файлы) — отключаемо.
- Конфиг `inside_the_system-common.toml` + GUI `/its config` (таймеры, прирост доверия, краши).
- Локализации EN/RU/ZH.

### The Broken Script (+ аддоны Additions / Reprogrammed)
- «Сломанный мир»: визуальные глитчи, случайные сообщения, искажённый чат, отключение/подмена команд.
- Много сущностей с разными ролями: пассивные (огонёк-телепорт, наблюдатель за спиной), агрессивные (выгоняет из пещер, ломает блоки, бессмертные, блокируют открытие GUI).
- **Кооперация сущностей**: Observe → если стоишь на месте, вызывает Report → Report сообщает позицию остальным.
- **Скрытая шкала угрозы (Purgatory Score)**: растёт от взаимодействия со структурами/сущностями и от бездействия → чаще события.
- Свои измерения: «пустота», попадание через особую смерть/провал события.
- Структуры-аномалии, «попытка получить OP», «бан» из мира.
- 4-я стена: файлы на рабочем столе, краши, «повреждение»/удаление мира; `/safemode`, `/tbs_config`.

### Общий знаменатель (что берём как жанровые механики)
1. Медленный разгон + скрытая шкала угрозы.
2. Наблюдение/сталкинг с исчезновением при взгляде.
3. Следы присутствия в мире (блоки, таблички, сундуки, факелы).
4. Фейковый «игрок» в чате + диалоги + система отношения.
5. Глитчи экрана/звука/интерфейса.
6. Несколько сущностей с ролями и общим «мозгом».
7. Особое измерение.
8. 4-я стена с явной настройкой безопасности.

Ключевые решения:
- **HorrorDirector** — центральный серверный планировщик (по `ServerTickEvent`), раз в N секунд бросает «кубик» с весами по стадии (день мира, DreadScore, Relationship, биом, время суток, пещера/поверхность). Каждое событие — класс `HorrorEvent` с `canRun()/run()/cooldown`. Это даёт расширяемость и тестируемость через `/hs trigger`.
- **Стадии** (по дням мира + DreadScore): 0 — тишина (дни 1–3); 1 — следы; 2 — наблюдение; 3 — контакт (чат/диалоги); 4 — агрессия/глитчи; 5 — финал (измерение, концовки).
- **Сетевые payload'ы** — все визуальные/4-стенные эффекты инициирует сервер, исполняет клиент; клиент сам проверяет режим безопасности перед любым действием вне игры.
- Данные: DreadScore/Relationship — NeoForge Data Attachments (сохраняются с игроком), глобальное состояние мира — `SavedData`.

## 3. Набор оригинальных механик (что реализуем)

**Сущности**
- `Listener` (главный): стоит на краю тумана/рендера, исчезает при взгляде (raycast от глаз игрока + dot product), смотрит из-за деревьев, в пещерах; в поздних стадиях подкрадывается сзади (CreepBehind). Неуязвим до финала.
- `Watcher` (пассивный): появляется, если игрок долго стоит неподвижно; через время вызывает `Reporter`.
- `Reporter`: «сообщает» позицию игрока остальным (ShareTargetGoal) → Listener получает точную цель.
- `Hollow` (агрессивный, поздний): ломает блоки на пути, выгоняет из укрытий, может блокировать открытие GUI на несколько секунд.
- Животные-индикаторы: волки/кошки рычат и смотрят в сторону сущности (миксин/goal-инъекция).

**Следы в мире**: кража/замена факелов на редстоун-факелы, тоннели 2×1, песчаные «столбы», вырубленные кроны деревьев, таблички с фразами (из lang/dialogue), «подарки» в сундуках (странные предметы с кастомными названиями), чужой полу-построенный дом рядом с базой.

**Чат и диалоги**: фейковое «X joined the game», сообщения от сущности, реакция на сообщения игрока (`ServerChatEvent` → DialogueTree с ключевыми словами), изменение Relationship; искажение текста (zalgo/подмена букв), фейковые системные сообщения («[Server] Integrity check failed»).

**Глитчи (клиент)**: пост-шейдер (RGB-сдвиг, шум, «битые чанки»), тряска камеры, принудительный поворот взгляда, подмена звуков, мигание HUD, смена текстуры неба, временное «зависание» кадра, фейковый экран загрузки чанков.

**Измерение `the_static`**: бесконечная пустота с обломками блоков и шумом; попадание при смерти от Hollow или провале финального события; выход — через квест/концовку.

**Концовки** (по Relationship): «Отпущен» (хорошая), «Запись стёрта» (плохая), «Цикл» (нейтральная). Плохая концовка — кульминация 4-й стены в выбранном режиме.

## 4. Режимы безопасности (4-я стена)

Конфиг `hollowsignal-client.toml`, поле `safetyMode = SAFE | HARDCORE`, плюс отдельные флаги. Переключение в HARDCORE только через GUI `/hs config` с экраном-предупреждением и вводом подтверждения; на сервере хардкор-действия выполняются только у клиента, который сам включил режим.

| Эффект | SAFE (по умолчанию) | HARDCORE (опционально) |
|---|---|---|
| «Ошибка» с посланием | Внутриигровой экран, имитирующий окно Windows | Настоящее системное окно (`tinyfd`/LWJGL MessageBox, либо `JOptionPane`) с текстом-посланием |
| Файлы на ПК | Записки только внутри мира (книги, таблички) | Создание **новых** `.txt` в случайной папке пользователя на диске C: — `C:\Users\<user>\` и её подпапки (Desktop, Documents, Downloads, Pictures, Music, Videos, а также случайные доступные на запись вложенные папки, найденные обходом до глубины 2–3). Папка игры не используется. Исключаются системные/скрытые каталоги (`AppData`, `.*`, `OneDrive`-заглушки без доступа). Путь Рабочего стола/Документов берётся через `SHGetKnownFolderPath`-эквивалент (`System.getProperty("user.home")` + проверка реальных путей, т.к. Desktop может быть перенаправлен в OneDrive). Уникальные имена, проверка `Files.exists` перед записью, `CREATE_NEW` — никогда не перезаписывает и не удаляет чужие файлы. Журнал созданных файлов (`.minecraft/hollowsignal/created_files.log`) + команда `/hs cleanup` удаляет только файлы из журнала |
| Краш | Фейковый экран краша внутри игры → возврат в меню | Сохранение мира → настоящий выход с кастомным crash-report (`hs-crash-*.txt`) |
| Выключение ПК | Фейковая «выключающаяся» чёрная заставка Windows | Флаг `allowPcShutdown` (отдельно, выкл. даже в HARDCORE): сохранение мира → `shutdown /s /t 60 /c "<послание>"` (Win), `shutdown -h +1` (Linux/mac) с отменой (`shutdown /a`) — у пользователя есть минута на сохранение работы |
| Заголовок окна | Без изменений | Смена заголовка окна игры (GLFW) |

Обязательные гарантии: никакого удаления/изменения файлов вне собственных; никаких сетевых запросов; мир сохраняется до краша/выключения; команда `/hs safemode` всегда мгновенно выключает хардкор; в мультиплеере хардкор-эффекты никогда не инициируются чужим игроком.

## 4a. Игра с друзьями (мультиплеер)

Поддерживаются LAN, выделенный сервер и хостинг (Essential/e4mc и т.п. — они просто дают обычный сервер).

**Серверная логика**
- Весь Director, сущности, следы и чат работают на сервере; клиент только рисует эффекты → одинаково в одиночке и мультиплеере.
- **DreadScore двухуровневый**: личный (attachment на игроке) + общий мировой (`SavedData`). Стадия = функция от дня мира и общего Dread; интенсивность событий для конкретного игрока — от личного.
- **Выбор цели**: Director выбирает «жертву» с весами — одиночки, игроки далеко от группы, в пещерах и в темноте получают больше событий. Группа вместе → меньше скримеров, больше «следов», которые видят все.
- Кулдауны per-player + глобальный, чтобы на сервере с 5 игроками не было спама событий; масштабирование по числу онлайн.
- Сущности знают про всех игроков: Listener исчезает, если на него смотрит **любой** игрок; Reporter передаёт цели всем сущностям; Hollow выбирает ближайшего.

**Кооперативные механики (новые, только в мультиплеере)**
- **Мимик друга**: Listener принимает ник и скин другого онлайн-игрока (GameProfile + skin из кеша клиента) и стоит вдали/пишет от его имени в чат «шёпотом» только жертве.
- **Раздельная реальность**: событие видно только одному игроку (пакеты только ему) — друг рядом ничего не видит. Клиентские «фантомные» блоки/сущности.
- **Фейковые сообщения от друзей**: искажённые копии реальных сообщений игроков, фейковый «X left the game» для игрока, который на самом деле онлайн.
- **Общая цель концовки**: Relationship считается на группу (среднее с весами), финальное событие в измерении `the_static` — для всех участников; кооп-задача (например, двое одновременно активируют «приёмники»).

**4-я стена в мультиплеере**
- Серверный конфиг `hollowsignal-server.toml`: `allowHardcoreEffects` (по умолчанию `true` — сервер разрешает, но **каждый клиент сам** включает HARDCORE у себя). Админ может запретить хардкор на сервере целиком.
- Сервер шлёт только «намерение» (`OsActionPayload` с типом и текстом); клиент выполняет, только если его локальный `safetyMode == HARDCORE` и соответствующий флаг включён. Сервер не может заставить клиента создать файл/выключить ПК.
- Краш/выключение в мультиплеере: у клиента — сохранение не нужно (мир на сервере), просто корректный дисконнект перед действием; на LAN-хосте сначала сохраняется мир.
- Контент посланий формируется из шаблонов в ресурсах мода (не произвольный текст от других игроков), чтобы чужой игрок не мог записать файл с произвольным содержимым на ПК друга.

**Синхронизация**: конфиг-синк сервер→клиент (стадии, веса), версия протокола в `neoforge.mods.toml`/payload registrar, мод обязателен на обеих сторонах.

## 5. Этапы разработки

1. **Каркас**: NeoForge 1.21.1 MDK (ModDevGradle), `neoforge.mods.toml`, `HSConfig`, команды `/hs`, lang en/ru. Проверка: `gradlew runClient` запускает игру с модом.
2. **Director + DreadScore + стадии**: тиковый планировщик, attachments, `/hs dread`, `/hs trigger`. Первые события-следы: факелы, таблички, сундуки, тоннели.
3. **Listener**: модель (player-like, GeckoLib не обязателен — HumanoidModel + своя текстура), исчезновение при взгляде, сталкинг в тумане, ForceLook-скример, звуки, реакция животных.
4. **Чат и Relationship**: фейковый join, DialogueTree из `data/hollowsignal/dialogue/*.json`, реакция на сообщения и действия игрока (атака/подарок/разрушение следов).
5. **Клиентские глитчи**: пост-шейдер, тряска, фейковые экраны (краш, ошибка, загрузка), подмена звуков.
6. **Вторичные сущности**: Watcher → Reporter → общий таргет; Hollow с ломанием блоков и блокировкой GUI.
7. **Измерение `the_static`** + концовки.
8. **4-я стена**: `FourthWallService` с SAFE/HARDCORE реализациями, экран предупреждения, флаги, `/hs safemode`.
9. **Мультиплеер**: выбор жертвы, per-player/глобальные кулдауны, мимик друга, раздельная реальность, серверный конфиг, групповая концовка. (Базовая серверная архитектура закладывается с этапа 2, здесь — кооп-механики и тесты.)
10. **Баланс и полировка**: веса событий, кулдауны, локализация, конфиг-GUI, звуковой дизайн.
11. **Релиз**: сборка jar, страница Modrinth/CurseForge с явным описанием хардкор-режима.

## 6. Верификация
- `gradlew build` — компиляция без ошибок; `gradlew runClient` / `runServer` — запуск.
- В игре: `/hs dread set 100`, `/hs trigger <event>` — проверить каждое событие вручную; `/time add` для проверки стадий по дням.
- SAFE по умолчанию: убедиться, что на свежей установке ни одно действие не выходит за пределы игры (проверить, что на Рабочем столе ничего не появилось, процесс не завершается).
- HARDCORE: включить через GUI, проверить создание файла (новый файл, без перезаписи), системное окно, краш с сохранением мира, `shutdown` с таймером и отменой `shutdown /a`.
- HARDCORE-файлы: проверить, что файлы появляются в разных папках `C:\Users\<user>\...` (включая перенаправленный в OneDrive Рабочий стол), не появляются в папке игры и в `AppData`, а `/hs cleanup` удаляет ровно их.
- Мультиплеер: `runServer` + два `runClient` (разные ники через `--username`), проверить выбор жертвы, мимик ника/скина друга, событие видное только одному игроку, отсутствие спама событий, что хардкор срабатывает только у клиента с включённым режимом и не срабатывает при `allowHardcoreEffects=false`.
- Выделенный сервер: убедиться, что клиентский код (окна, файлы) не грузится на сервере (`Dist.CLIENT`), а хардкор-эффекты не применяются к игрокам, которые их не включили.
